# Детекция повреждений посылок на YOLOv8

## Задача
Разработка модели компьютерного зрения для автоматической модерации страховых случаев.
Цель - определять наличие повреждений на фотографиях посылок для снижения нагрузки на ручную проверку.

## Технологии
- Модель: YOLOv8n (Ultralytics)
- Фреймворк: PyTorch
- Обработка данных: Python, OpenCV
- Инструменты: Git, VS Code

## Данные и подготовка
Для обучения были использованы два открытых датасета с платформы Roboflow Universe:
1. Damage Package Detection (5 классов). Ссылка: https://universe.roboflow.com/bhagyashri-biradar/damage-package-detection/dataset/5
2. Package Computer Vision (2 класса). Ссылка: https://universe.roboflow.com/deteksipaketrusak/package-kglu1/dataset/2

## Анализ данных
В ходе исследования исходных датасетов были выявлены следующие особенности:
1. Разные условия съемки. Первый датасет содержит цветные изображения с разным освещением. Второй датасет состоит из черно-белых фотографий.
2. Мультиракурсность. Второй датасет содержит серии фотографий одних и тех же объектов с разных ракурсов, что создает риск переобучения модели на внешний вид конкретных посылок.
3. Разнородность объектов. На фотографиях присутствуют не только картонные коробки, но и мягкие пакеты, которые имеют другую форму и специфику повреждений (разрывы вместо вмятин).

Данные особенности были учтены при формировании объединенного датасета для повышения робастности (устойчивости) финальной модели.

## Эксперименты и результаты

### Этап 1: Базовое обучение (5 классов, 104 изображения)
Модель показала mAP50 = 0.7, но Recall для повреждений составил 0.611. Модель пропускала 39% дефектов из-за малого количества данных и размытия внимания на редких классах.

### Этап 2: Попытка объединения данных (5 классов)
Для повышения качества было решено объединить два датасета. Был написан скрипт `merge_datasets.py`, который копировал изображения и пересчитывал индексы классов (так как в исходных датасетах они не совпадали).
Однако тест на 15 эпохах показал падение метрик: mAP50 упал до 0.621, а Recall для повреждений — до 0.457. 
Анализ показал, что причина в конфликте разметки: в одном датасете "открытая коробка" считалась повреждением, в другом — нет. Модель не могла выучить общие признаки из-за противоречивых данных.

### Этап 3: Переход к бинарной классификации (Финальная модель)
Была выдвинута гипотеза: для бизнес-задачи важнее бинарное решение (есть дефект / нет), а не тип дефекта (вмятина, дырка, мокрая коробка). 
Был написан новый скрипт `merge_datasets_2class.py`, который свел все типы повреждений из обоих датасетов в один класс `damaged`, а целые коробки — в `package`. 

Для проверки корректности нового формата данных был проведен быстрый тест на 15 эпохах (mAP50 = 0.708, Recall = 0.359). Результаты подтвердили, что данные размечены верно, и модель начала сходиться.
После этого модель была обучена на 100 эпохах со следующими результатами:
- mAP50 (все классы) = 0.794
- Recall (damaged) = 0.555
- Precision (damaged) = 0.705

### Этап 4: Сравнение с изолированным датасетом
Для проверки гипотезы о том, что черно-белые изображения и мультиракурсность второго датасета могут негативно влиять на модель, был проведен эксперимент. Модель, обученная только на втором датасете (50 эпох), показала mAP50 = 0.79 и Recall = 0.55. 
Модель, обученная на объединенном датасете (100 эпох, цветные + ЧБ фото), показала mAP50 = 0.794 и Recall = 0.555. Это доказывает, что объединение разнородных данных не ухудшило качество, а сделало модель более устойчивой к разным условиям съемки, что критически важно для реального продакшена.

По графикам потерь (val/box_loss, val/cls_loss) видно, что после ~60-й эпохи модель начинает переобучаться: потери на валидации перестают падать, а метрики mAP50 и Recall выходят на плато. Это говорит о том, что модель достигла предела для текущего объема данных.

Анализ матрицы ошибок показал:
- Модель отлично локализует сами посылки (99%).
- 86% повреждений определяются верно.
- 14% повреждений остаются незамеченными (False Negatives). Скорее всего, это мелкие дефекты, повреждения на черно-белых фото или на мягких пакетах, где границы повреждения размыты.
- 8% ложных срабатываний (когда целая посылка помечается как поврежденная).

Для дальнейшего улучшения модели (снижения False Negatives) необходимо добавить больше размеченных данных с мелкими повреждениями, а также применить аугментации, имитирующие разные условия освещения и съемки.

## Выводы

В ходе экспериментов были получены следующие результаты:
- Базовая модель (104 чистых фото, 5 классов): mAP50 = 0.7, Recall = 0.611.
- Финальная модель (1130 фото, 2 класса, ЧБ + пакеты): mAP50 = 0.794, Recall = 0.555.

На первый взгляд может показаться, что базовая модель находит больше повреждений (61% против 55%). Однако это сравнение некорректно. 

Базовая модель обучалась на маленьком, но однородном датасете (идеальные цветные фото). Финальная модель обучалась на "грязных" данных: черно-белые снимки, мягкие пакеты (где повреждения выглядят иначе, чем на картоне) и разные ракурсы. 

Финальная модель показала уверенные результаты (mAP50 = 0.794) на сложных данных, что делает её более пригодной для использования в реальном продакшене, где условия съемки всегда разнородны.

Для дальнейшего повышения Recall (снижения пропусков повреждений) модели требуется больше данных, аналогичных первому датасету: качественные цветные фотографии повреждений при хорошем освещении. Добавление таких данных в обучающую выборку позволит модели выучить более четкие признаки дефектов.

## Как запустить
1. Клонировать репозиторий.
2. Установить зависимости: `pip install -r requirements.txt`
3. Скачать датасеты по ссылкам выше.
4. Запустить обучение: `python train.py`
5. Запустить инференс: `python predict.py`
